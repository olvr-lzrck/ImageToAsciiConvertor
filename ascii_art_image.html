1. upload & pixel decoding

When you select an image, the browser reads it as a Data URL and decodes it into an Image object. We then draw this image onto a hidden <canvas> element to access the raw pixel data using getImageData().

  • FileReader API: Converts the file to a base64 string.
  • Canvas 2D Context: Provides pixel-level access to the image.
  • Pixel Array: A Uint8ClampedArray containing RGBA values (0–255) for every pixel.

This gives us raw access to the image data without any lossy compression artifacts.

2. grayscale conversion

Each pixel's RGB values are combined into a single luminance (brightness) value using the ITU‑R BT.709 standard formula.

  • Why these coefficients? The human eye is most sensitive to green, followed by red, and least sensitive to blue.
  • Formula: Y = 0.299·R + 0.587·G + 0.114·B
  • Result: A single value per pixel representing perceived brightness (0 = black, 255 = white).

This mimics how the human visual system processes light, creating a more natural grayscale representation.

3. smart resizing & aspect ratio

The image is resized to match your desired characters per line. The height is calculated automatically to preserve the original aspect ratio.

  • Monospace correction: ASCII characters in monospace fonts are roughly 0.52× as wide as they are tall.
  • Formula: height = width / aspect * 0.52
  • Scale factor: Multiplies the width before conversion, giving you finer control over detail.

This ensures the final ASCII art doesn't look vertically stretched or compressed.

4. image enhancement (contrast & sharpen)

Optional preprocessing steps to improve the final ASCII quality:

  • Contrast: Pushes mid‑tone values toward black or white using (value - 128) × 1.5 + 128. This makes dark areas darker and light areas lighter.
  • Sharpen: Applies a Laplacian kernel ([0,-1,0; -1,5,-1; 0,-1,0]) to emphasize edges.
  • Effect: Contrast improves readability; sharpen adds crispness to fine details.

These are applied before the brightness mapping for maximum impact.

5. brightness → character mapping

Every grayscale pixel value (0–255) is mapped to a character from the chosen charset:

  • Index calculation: charIndex = Math.round(brightness / 255 * (charset.length - 1))
  • Dark pixels get dense characters like @, #, 8.
  • Bright pixels get sparse characters like ., ', or space.
  • Invert: Reverses the mapping by using 1 - brightness.

The 'vibe' charset is hand‑tuned for smooth gradients and high contrast across all brightness levels.

6. rendering & export pipeline

The final character grid is displayed and exported in three formats:

  • PNG (raster): Each character is drawn onto a canvas using a monospace font. The canvas size is calculated from the character grid dimensions and font metrics.
  • SVG (vector): The ASCII text is wrapped in an SVG <text> element with a monospace font, preserving resolution independence.
  • TXT (plain): The raw string is saved as a text file, perfect for further editing or sharing.

All exports use your current font selection and preprocessing settings, ensuring consistent results across formats.

what does "scale" do?

The scale factor multiplies the resolution of the image before it's converted to ASCII.

How it works: Your image is resized to width × scale pixels, then each pixel becomes one character. So with 80 chars/line and 2× scale, the image is sampled at 160 pixels wide — capturing much more detail.

• 0.25× – 0.5×: Smaller sample grid = blockier, but much smaller output.
• 1×: One pixel per character — crisp and balanced.
• 2× – 4×: More pixels per character = finer detail, but larger file size.
